# API fields

Every GET route's response, field by field, with an example from a unit's own answer.
Generated by `tools/api_fields.py` from the meanings in `tools/api_fields_meanings.py`;
`API.md` lists every route (writes too) and `API_INVENTORY.md` who uses each and what is
missing.

- **Paths:** `a.b` is a field of an object, `a[]` an array's elements, `a{key}` the values
  of a map keyed by an id (a talkgroup, an LCN, a site).
- **Types:** "absent when ..." means the key is left out; "or null" means it is sent as
  null. `number` covers integers and decimals.
- **Times:** fields ending `_unix_ms` and the `first_ms`/`last_ms`/`at_ms` stamps are
  milliseconds since 1970 (UTC); other `_ms` fields are durations.
- **Examples** come from the unit the document was made on; an empty one was not in its
  answer.

## `GET /api/v1/session`

Who the client is: whether a password is set (`protected`), its level (`admin`, `listener`, null: not signed in) and how it is known (`open`: no password is set, `session`, `token`).

| Field | Type | Example | Meaning |
|-------|------|---------|---------|
| `protected` | bool | `false` | An administrator's password is set: clients sign in. False: the radio is open, and every client is the administrator. |
| `level` | string or null | `"admin"` | The client's level: `admin` or `listener`; null: not signed in. |
| `via` | string or null | `"open"` | How it is known: `open` (no password is set), `session` (a browser's cookie) or `token`. |

## `GET /ca.crt`

The unit's CA certificate (PEM), for a PC to install so that its browser and tools trust the unit's HTTPS; open to a client that is not signed in, and served over plain HTTP too.

The certificate of the unit's CA (PEM, `application/x-x509-ca-cert`, an attachment named `fishball-scanner-ca.crt`): installed on a PC as a trusted root it makes the unit's HTTPS trusted, and given to a tool as `SCANNER_CA` likewise. It can sign only for private addresses and local names. Anyone may read it, and it stays on the plain HTTP port after a password is set, when every other request there is sent to HTTPS: a PC needs it before it can trust the other port. Hold its SHA-256 against `GET /api/v1/certificate`'s `ca_sha256` as Settings, Access shows it.

## `GET /api/v1/certificate`

The unit's HTTPS: its port, the CA's name and the SHA-256 of its certificate (to hold against what a PC shows), the names the certificate is for, those left out because the CA signs only private addresses and local names, and when it ends.

| Field | Type | Example | Meaning |
|-------|------|---------|---------|
| `https_port` | number or null | `8443` | The port HTTPS is served on; null: it is not served (the certificate could not be made). |
| `ca_name` | string | `"Fishball scanner pluto 3431a941"` | The name of the unit's CA, as a PC lists it once installed. |
| `ca_sha256` | string | `"3acc0cbc2a95b71a3c4f1470da5743d7bfde...` | SHA-256 of the CA's certificate (64 hex digits), to hold against the fingerprint a PC shows for the file from `GET /ca.crt`. |
| `names` | array | `["127.0.0.1", "192.168.120.50", "192....` | The addresses and names the unit's certificate is for: those the unit is reached by now. |
| `names[]` | string | `"127.0.0.1"` | An address, or a host name. |
| `left_out` | array | `[]` | Addresses and names the unit has that its CA may not sign for (a public address, a name that is not local, a name that is not a host name as a certificate writes one): HTTPS by one of them is not trusted. |
| `left_out[]` | string |  | An address, or a name. |
| `not_after_unix_s` | number | `1865203200` | When the certificate ends. It is made again 30 days before, when the unit's addresses or names change, and once the clock is set. |

## `GET /api/v1/access/iiod`

The administrator's: libiio's daemon (`iiod`: port 30431 on the network, and the USB gadget's IIO function), which lets another program use the board as a tuner and so retune it under the scanner. Whether the system has its switch (`available`), the choice kept (`wanted`) and whether it runs now (`running`).

| Field | Type | Example | Meaning |
|-------|------|---------|---------|
| `available` | bool | `true` | The unit's firmware has the switch. False (a PC, an image from before it): nothing here switches libiio's daemon, and where it is installed it runs always. |
| `wanted` | bool | `false` | The choice kept on the flash: on at every start. A unit is off unless it was switched on. |
| `running` | bool | `false` | libiio's daemon runs now. True with `wanted` false: it was switched on until the unit restarts (`until_restart` on the `PUT`; the bench does that). |

## `GET /ws/live`

The radio's state pushed as it changes: a snapshot, then status, traffic channels, calls, recordings, alert tones, the live site's talkgroups, the scan and configuration changes; and what a page subscribes to (the spectrum, the event log, the radio's readback, the window, the crystal, live TV, the download running, data mode's listening, the analog receiver).

A WebSocket of text frames, each a JSON object with `type`; the payload is under the key named:

| `type` | Key | When |
|--------|-----|------|
| `snapshot` | `status`, `calls` (`open`, `recent`), `traffic`, `talkgroups`, `scan`, `atsc` | On connect, and after `lag`. |
| `status` | `status` (as `GET /api/v1/status`) | Each second, and at once when the live site changes. |
| `traffic` | `traffic`: `channels[]` (each traffic channel: `lane`, `tuned_hz`, `following_tg`, `on_data_channel`, `voice_frames`, `last_voice_ms_ago`, `call`) and `open[]` (every call on the air) | When a traffic channel changes. |
| `call_opened`, `call_closed` | `call` (as `GET /api/v1/calls/{id}`) | As a call opens or closes. |
| `talkgroups` | `talkgroups` (as `GET /api/v1/talkgroups`) | When the live site changes, an alias, the listening settings or what decides recording change, or a call opens on a talkgroup not listed yet. Between them a page keeps `last_ms` current from the calls it is pushed. |
| `recording` | `recording` (as an item of `GET /api/v1/recordings`) | As a recording is saved. |
| `alert` | `call`, `alerts` (each as an item of `GET /api/v1/activity/alerts`, `dispatch` null) | When a closed call's alert tones are known, after its recording. |
| `scan` | `scan` (as `GET /api/v1/scan`) | While a scan runs, as its progress or found sites change. |
| `atsc` | `atsc` (as `GET /api/v1/atsc/scan`) | While a TV scan runs, as its progress or the channels read change. |
| `changed` | `what`: `radio`, `systems`, `hold`, `recordings` or `access` | After a write changed that part: read it again. |
| `lag` | | The listener fell behind; a snapshot follows. |

What only some pages show comes while the page asks for it. It sends `{"type": "subscribe", "spectrum": bins, "events": {"after": seq, "routine": bool, "part": name}, "radio": bool, "window": bool, "crystal": bool, "atsc_live": bool, "files": bool, "data": bool, "analog": bool}` (each field optional; each subscribe replaces the last, and what it asks for comes at once):

| `type` | Key | When |
|--------|-----|------|
| `spectrum` | `spectrum` (as `GET /api/v1/spectrum`, in `bins`) | Each new spectrometer frame (7.6 a second at most). |
| `events` | `events` (as `GET /api/v1/events`' `events`) | As the event log grows past `after` (housekeeping too with `routine`; one part's lines with `part`). |
| `radio` | `radio` (as `GET /api/v1/radio`) | Every 3 s. |
| `window` | `window`: `plan` (as `GET /api/v1/sites/{id}/plan`, null with no site live) and `survey` (as `GET /api/v1/survey`) | Every 5 s. |
| `crystal` | `crystal` (as `GET /api/v1/radio/crystal`) | When it changed, each second at most. |
| `atsc_live` | `live` (as `GET /api/v1/atsc/live`) | When it changed, each second at most. |
| `files` | `download` (as `GET /api/v1/files`' `download`; null when none runs) | When it changed, each second at most. |
| `data` | `data` (as `GET /api/v1/data`) | When its `rev` moved: at each burst, and once a second while it listens. |
| `analog` | `analog` (as `GET /api/v1/analog`) | When its `rev` moved: at a tuning, when the squelch opens or shuts, and four times a second with the meter while it listens. |

## `GET /ws/analog`

The analog receiver's audio while it listens: a text frame `{type: format, rate_hz}` (31,250), then binary frames of 20 ms, 16-bit little-endian mono; none while its squelch is shut; a listener that falls behind gets `{type: lag, skipped}`.

A WebSocket. A text frame `{"type": "format", "rate_hz": 31250}` first; then, while the receiver listens and its squelch is open, binary frames of 20 ms of mono 16-bit little-endian audio at that rate (625 samples). Nothing comes while the squelch is shut or another mode has the radio. A listener that falls behind gets `{"type": "lag", "skipped": n}`.

## `GET /ws/audio`

Live audio: with `v=2` every lane, each binary 20 ms frame tagged with its lane (text meta, alert and lag frames); without, lane one untagged.

A WebSocket. Binary frames are 20 ms of 8 kHz mono 16-bit little-endian audio (160 samples). With `?v=2` every lane is sent and each frame starts with 4 bytes `[lane, 0, 0, 0]` (lane 0 or 1); without it, lane 1 only and no header. Text frames:

| `type` | Fields | When |
|--------|--------|------|
| `meta` | `lane` (0 or 1), `tg`, `src` (0: unknown), `call_id`, `speaker` (`both`, `left`, `right`, `off`) | Before a lane's first frame of a new call or talker. |
| `alert` | `lane`, `tg`, `call_id`, `seq`, `kind`, `tones_hz`, `offset_ms` | With `v=2`, before the frame that makes the call's audio an alert tone; it began `offset_ms` into the call's audio. |
| `lag` | `skipped` | The listener fell behind; frames were skipped. |

## `GET /api/v1/playlist`

Every system as an SDRTrunk playlist (XML): a channel for each site on its control channel and those that take over from it, each system's aliases as a list named after it (`download=true`: as a file).

An SDRTrunk playlist (`application/xml`; with `download=true` an attachment named `scanner-playlist.xml`): `<playlist version="4">` with an `<alias>` for each alias of each system (its `list` the system's name; its IDs, a `priority` of -1 when never followed and a `record` as `<id>` elements) and a `<channel>` for each site (`system`, `site`, the control channel as its tuner frequency, or with the channels that take over from it as the frequencies SDRTrunk rotates through; a DMR site's channel numbers as `<timeslot>`). SDRTrunk's own reader reads it (`tools/sdrtrunk_playlist_reference.py`). A talkgroup's traffic lane, a site's identity and what a site learned are not in it.
