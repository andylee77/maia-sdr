**Date:** 2026-04-16
**Branch:** `fishball-p25`
**Final BUILD_TAG:** `2026-04-16-bake2-constellation-pi4-reference`

## Summary

Two-part change. On the HDL side, the traffic chain gains full
`iq_packer` + `iq_dma` parity with the control chain (post-DDC IQ
capture at 62.5 kSPS streamed to DDR, new register bank at 0xE0,
new AXI master `m_axi_traffic_iq` on HP1, new DMA ring at
`0x1C00_0000`). Also mirrors the Phase 8C.1 `lsm_ctrl_dom` revert
onto the traffic side — both LSM chains now live in the global
`sync` domain, relying on the explicit `reset_in` pulse (Phase 8A)
+ decimator strobe gating for per-call reset.

On the PS / dashboard side, a dense batch: SDRTrunk-parity
API rename (`/api/lsm_* → /api/control_*`), C4FM/LSM modulation
selector with auto-detect, narrowband software FFT over the iq
rings, IQ constellation scatter via the retired Phase 6D software
demod, per-call recording + playback, browser-pushed NTP fallback
for isolated-network boards, NTP-on-boot SNTP client, P25 phase
inference (P1 vs P1+P2) from `IDEN_UPDATE_TDMA` TSBKs, new
`GroupVoiceChannelGrantUpdateExplicit` (opcode 0x03) parser that
closes the SDRTrunk encryption-gate parity gap, dashboard
symmetric retune controls (center / BW / auto-LO), and the stale
`follower_rx_lo` fix.

## HDL changes (bake #2)

### `maia-hdl/p25_hdl/config.py`

New traffic IQ DMA config. Address `0x1C00_0000`, 256 KB ring (8
× 32 KB sub-buffers), aligned. Matches control `iq_dma` geometry
exactly.

```python
self.traffic_iq_dma_address = 0x1C00_0000
self.traffic_iq_dma_num_buffers_log2 = 3
self.traffic_iq_dma_buffer_size = 0x8000
```

Plus the `@property` accessors + validate() alignment assertion.

### `maia-hdl/p25_hdl/p25_top.py`

1. New interrupt field `traffic_iq_dma` in the control register
   bank's `interrupts` Rsticky.
2. New `TrafficIqPacker` + `TrafficIqDma` (reusing `IQPacker` and
   `DmaStreamRingWrite` modules) instantiated in the P25Core
   constructor. New `m_axi_traffic_iq` port.
3. New register bank at offset `0xE0` (bank 7, the last slot in
   the 3-bit decoder). Layout mirrors `iq_registers`:
   ```
   traffic_iq_dma_status  [0]   traffic_iq_overflow (Rsticky)
                          [18:16] last_buffer
   traffic_iq_dma_control [0]   traffic_iq_enable (RW)
   traffic_iq_next_address [31:0] next_address
   ```
4. Elaborate() wiring:
   - `traffic_iq_packer` taps `traffic_ddc.re_out/im_out/strobe_out`
     (same signals feeding `traffic_c4fm` and the traffic LSM chain)
   - DMA stream handshake as in control side
   - New `PulseSynchronizer` for the `traffic_iq_dma` interrupt
   - Crossbar `traffic_iq_regs_select` + rdata/rdone/wdone fan-in
     + address/wdata routing
   - Sync-domain CDC output wiring
5. **Phase 8C.1 revert mirror on traffic side**: removed
   `lsm_traffic_dom = ClockDomain(...)` + `lsm_traffic_renamer` +
   the `ClockSignal/ResetSignal` wiring. `traffic_lsm_demod`
   instantiated directly in the global `sync` domain (matching
   the 2026-04-15 control-side revert).

All 8 register banks are now used; any further bank needs a 4-bit
decoder (bits [6:3]).

### New TSBK parser: `GroupVoiceChannelGrantUpdateExplicit` (0x03)

Previously opcode 0x03 fell into the `Unknown` catch-all. Many
P25 sites (especially TDMA-capable + split-TX/RX-frequency) emit
this variant instead of plain GVCG, so we were missing a chunk of
grants — and importantly missing the `service_options.encrypted`
bit that closes the SDRTrunk encryption-gate parity gap.

New `TsbkMessage::GroupVoiceChannelGrantUpdateExplicit` variant
with fields {transmit_channel, receive_channel, talkgroup,
service_options}. Parser at `decode_grp_v_ch_grant_update_explicit()`.
Handler in `control_channel.rs` emits a standard GrantEvent with
the encrypted + emergency flags set from the service_options byte.

### Chain-symmetry fix: `active_modulation` state + auto-detect

New `AppState.active_modulation: Arc<AtomicU8>` (0=Auto, 1=C4FM,
2=LSM). Background task in main.rs compares
`decoder.nid_decoded_ok` delta vs `lsm_decoder.nid_decoded_ok`
delta once per second when in Auto mode. Picks whichever chain
is producing more BCH-valid NIDs. Manual overrides (1 or 2)
freeze the selection.

`AppState.active_control_decoder()` helper returns a reference to
the active `ControlChannelDecoder`. Dashboard handlers
(`get_system`, `get_grants`, `get_bands`, `get_stats`) refactored
to use it.

### Phase inference (P1 vs P1+P2)

New `has_tdma_band: bool` field on `SystemIdentity`. Sticky-
latched to true when any `opcode_byte == 0x33`
(IDEN_UPDATE_TDMA) TSBK passes CRC. Surface via new
`phase: Option<String>` on `SystemInfo` — either `"P25 P1"` or
`"P25 P1+P2"`. Dashboard System Type row combines modulation
label with phase: `"LSM · P25 P1+P2"`.

Verified live: Clay County shows P25 P1+P2 (has a B8 TDMA band
we didn't expect), matching what SDRTrunk would show with the
same signal-derived approach.

### Stale `follower_rx_lo` fix

Previously the grant follower captured `args.rx_lo` once at spawn.
If `/api/reinit?rx_lo=…` moved the LO mid-session, the follower
computed wrong offset_hz on subsequent grants.

Fix: `AppState.current_rx_lo: Arc<AtomicI64>` initialized from
`args.rx_lo`, updated by `get_reinit` on successful LO set, read
fresh by the follower on every retune.

## Sequencing for rollback

Bake #1 (1R1T + temp-sense, doc 043) and bake #2 (this doc) are
independent bitstreams — rolling either back doesn't require
rebuilding the other. Binary reflash + DTS reflash needed for
bake #2 though, since the PS-side `RxBuffer::new("p25-traffic-iq")`
call depends on the Tezuka DTS having `p25-traffic-iq` defined.

If bake #2 needs to be reverted: flash the pre-bake-#2 XSA, roll
back the DTS `p25-traffic-iq` node + the
`traffic_iq_dma_address` config line, rebuild the firmware.
p25-httpd binary can stay the same — it falls through gracefully
when the UIO device doesn't exist.
