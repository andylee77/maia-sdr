# 051 — Seeds live: heartbeat snapshot + retune write-back + LoS detector

**Date:** 2026-05-03
**BUILD_TAG:** `2026-05-03-seeds-live`
**Bake required:** NO — pure PS change against the
`2026-05-03-seeding-bake` HDL (doc/changes/050). PAC was regenerated by
`build_fpga.bat --p25` and now exposes the bank 8 seed registers.

## What this lands

Five PS-side changes that turn the dormant bank-8 seed registers from
050 into a live warm-start path on every retune, plus two operator-UX
fixes the bake landed alongside (LoS close trigger, recording_saved
ws-event).

## 1. Seeds live (the bake earns its keep)

### Heartbeat snapshot (control chain)

`p25-httpd/src/app/seed_snapshot.rs` (NEW): rolling clean-sample
window + median commit. Captures only on tick where:

- `nid_event && nid_valid` (BCH-validated NID)
- `sync_distance == 0` (framer found 48-bit SYNC with zero Hamming
  distance)
- `!bch_busy` (BCH not mid-sweep)

Anything else is between-PTT noise that corrupts the median (memory:
2026-05-03 session, "AGC: needs PTT-time sampling"). Window is 32
samples; commits the median once `MIN_CLEAN_SAMPLES = 6` clean
snapshots have arrived (~1 s of clean signal at ~6 NID/s).

3 unit tests — warmup-then-commit, outlier rejection via median,
rolling-window eviction. All pass.

### Hardware helpers

`p25-httpd/src/hardware/fpga.rs`:

- `IpCore::write_traffic_seeds(agc, pll, timing)` — writes all three
  bank-8 traffic seed registers, then round-trips a read on
  `traffic_lsm_pll_seed` as a CDC fence. Without the fence, bank 8
  (seeds) and bank 6 (`traffic_lsm_reset` Wpulse) cross independent
  RegisterCDC instances and the reset can fire before the seed
  values cross the s_axi_lite → sync CDC. The read costs ~100 ns
  per retune.
- `IpCore::write_control_seeds(...)` — symmetry helper, not used in
  live operation but exposed for manual diagnostic writes.
- `IpCore::read_traffic_seeds() -> (u32, i16, i32)` — reads back
  the currently-latched seed values for `/api/system` surfacing.
- `sign_extend_18(raw: u32) -> i32` — module helper for the 18-bit
  signed timing seed (PAC surfaces as u32).

### Retune integration

`IpCore::retune_traffic_chain` extended with an
`Option<(u32, i16, i32)>` seeds parameter. When `Some`, seeds are
written before the reset pulse fires. When `None`, legacy cold-start
behaviour preserved.

`p25-httpd/src/app/grant_follower.rs::spawn_grant_follower` accepts
a new `follower_converged_seeds: ConvergedSeedsShared` parameter.
Before each freq-change retune it lifts the current snapshot from the
shared `RwLock`, passes it to `retune_traffic_chain`, and emits an
`info!` log line showing the seeds applied (or "cold-start" if the
heartbeat is still warming up).

`p25-httpd/src/httpd/api/traffic.rs` manual `/api/traffic` retune
passes `None` — operator sweeps want cold-start to expose the
freq-vs-acquisition relation without the warm-start mask.

### Surfacing

`/api/system` gains a `converged_seeds` field:

```json
{ "armed": true,
  "agc_seed_q9_11": 24576,
  "pll_seed_q2_13": -13,
  "timing_seed_q5_12": 30000,
  "samples_in_window": 32,
  "total_clean_samples": 184,
  "age_ms": 410 }
```

`armed = false` means the heartbeat is still warming up
(< MIN_CLEAN_SAMPLES clean NIDs).

## 2. Loss-of-sync close trigger

`CallBoundaryKind::TrafficNidObserved` (NEW) — broadcast from the
traffic-LSM heartbeat on every `nid_event` strobe (before TG/valid
gates so pre-call NIDs count toward "framer alive").

`CloseReason::SyncLost` (NEW) + `last_nid_at_ms` field on
`ActiveCall`, initialised to the open timestamp. The lifecycle tick
closes with `SyncLost` when `now - last_nid_at_ms > LOS_TIMEOUT_MS`
(1.5 s ≈ 8 missed LDUs). Sits alongside the existing 10 s `Timeout`
backstop — LoS fires fast when the chain stops finding sync mid-call;
Timeout is the slow safety net for legitimately-ended calls we missed
the TDU on.

`tracing::info!` line on each LoS close shows `(call_id, tg, freq,
nid_age_ms)` so the diagnostic trail is grep-able. Recorder match arm
extended (`"sync_lost"`); `serde_json` `rename_all = "snake_case"`
auto-renders the new variant for any future dashboard consumer.

## 3. recording_saved ws-event push

`recorder::finalize` now takes an
`Option<broadcast::Sender<String>>` and emits a
`{ "event_type": "recording_saved", "recording": <RecordingEntry> }`
event after the entry is pushed to the store.

Dashboard `/ws/events` handler intercepts the event and triggers an
immediate `refreshRecordings()` call rather than queuing into the
activity-log render path.

Eliminates the ~4 s lag between call close and Recent Calls row
update (operator-flagged 2026-04-30).

## 4. Plots: chain-aware narrowband label

`dashboard.html`: `Narrowband spectrum (post-DDC, ±X kHz)` dropdown
option label now switches based on the Chain selector
(±31.25 kHz for control, ±25 kHz for traffic). Status line still
shows the actual span from the API response — this just keeps the
dropdown honest before the user clicks.

## 5. /api/spectrum?chain=traffic relinked

`debug.rs::get_spectrum` was returning `Vec::new()` for chain=traffic
— a stub left over from the 2026-05-02 M2A pivot that was never
updated when the 2026-05-03 dual-DDC pivot added the new
`traffic_ddc.re_out / im_out → traffic_iq_dma` ring (50 kSPS, Nyquist
±25 kHz).

`p25-httpd/src/hardware/fpga.rs`:

- `IpCore::traffic_iq_dma: RxBuffer` field opened from
  UIO `p25-traffic-iq` (Tezuka DT carve-out at 0x1c000000, 32 KB
  buffers, see `tezuka_fw/board/tezuka/fishball7020/dts/fishball-p25.dtsi:190`).
- `IpCore::traffic_iq_last_addr: Option<u32>`.
- `IpCore::read_traffic_iq_buffers() -> Vec<&[u8]>`.
- `DmaChannel::TrafficIq` variant + match arm in
  `read_dma_buffers`.

`debug.rs::get_spectrum` now calls `read_traffic_iq_buffers()` for
chain=traffic.
